# LyricsX 2.0.12

维护者：Zikai Wang

重写悬浮窗和逐字歌词的动效逻辑，修复切句残影、闪烁、文字向右偏移以及两行主歌词与翻译重叠的问题。保留液态玻璃、模糊、轻微回弹、逐字高亮、辅助文字、拖动、点击穿透和位置记忆。

## 连续切句与增量显示

- 悬浮窗始终只绘制一个当前歌词块，不再保留等待动画结束的上一句。下一句与主歌词使用相同的换行排版，通过位置和缩放衔接，避免中途换行闪动。
- 辅助文字在主歌词移出其区域后渐显，避免翻译和下一句挤进运动中的主歌词。
- 相邻歌词严格按末尾追加内容、且时间间隔不超过 1.2 秒时，已有文字保持位置，新增部分独立出现。按 Unicode 字素比较；用于预留排版的后续文字不会提前画出。
- 快速切句的动画时长随行间隔缩短，动画进度直接由时钟计算，不等待上一段动画完成。主窗口自动滚动也按快速段缩短响应。
- 修正带辉光文本向右偏移 12 pt 的问题；按实际单行或双行预留主歌词高度，并独立预留辅助行间距，防止重叠。

## 自适应悬浮窗

- 默认按当前整句的尺寸调整宽高；“设置 → 悬浮窗 → 外观”可关闭自适应，或指定最小、最大宽度。原来的窗口宽度作为上限，默认最小宽度为 320 pt。
- 宽度按 40 pt 档位变化，小于两个档位的收缩保持原尺寸。短句至少稳定 1.25 秒、距最近扩展至少 1.6 秒后才收缩；高速长短句交替时保持可容纳它们的尺寸。
- 长句扩展约 0.28 秒，收缩约 0.42 秒，使用平滑非线性曲线。固定顶部和水平中心；屏幕边缘保留可见范围，并兼容旧位置记忆。
- 连续追加文字预留完整前缀链所需空间，避免逐字符改变窗口尺寸。翻译和下一句的可读宽度也纳入下限。
- 原生窗口边界、玻璃和控制条平滑缩放；承载歌词的视图、排版画布和 HDR 层持续复用，不跟着每一帧重新测量整个悬浮窗。

## 逐字、长音与 HDR

- 根据歌词源的实际词、音节或字符时间连续提亮和轻微放大，保留原有文字排版、标点及换行。
- 慢唱片段的辉光渐进增强，超过约 0.45 秒开始具备效果，约 1.6 秒达到完整强度；普通一秒左右的慢唱更容易看见，快速字符避免强烈闪光。
- “设置 → 歌词 → 逐字动效”可分别开关放大、长音辉光和 HDR。HDR 默认关闭，亮度默认 1.6×，新增 1.0×–4.0× 调节并保存设置。
- HDR 输出受显示设备与系统实际余量限制；普通显示模式继续使用 SDR。参考 [Apple HDR 颜色接口](https://developer.apple.com/documentation/swiftui/color/headroom(_:))。
- “减少动态效果”关闭位移、放大和辉光，保留同步提亮。没有逐字时间的歌词仍可使用行级或增量动画。

## 绘制与性能

- 活动歌词独立使用 60 Hz 动画调度，直接读取受约束的单调播放时钟；不是按进度条更新频率跳动。60 Hz 是请求的调度频率，实际帧率取决于系统负载与显示设备。
- 缓存文字测量结果；文字、字体、换行环境或尺寸变化才失效。逐帧变化集中在绘制与变换，暂停、隐藏及时间片段之间的长间隔不持续绘制。
- 保留较低频的播放器状态、进度条更新和后台检查；拖动进度立即更新。没有新增每个词独立运行的任务队列。

## 验证与安装

163 项测试通过。新增回归包括：

- 单行、两行自定义文字与原生 Text 的像素边界一致。
- 换句第一帧与旧下一句的像素位置一致，旧主歌词区域没有残留。
- 不同窗口宽度和字号下，两行主歌词、翻译、下一句保持分离。
- 增量文字不移动已有部分，也不提前显示未来文字。
- 独立绘制时钟在两次常规 tick 之间连续前进，暂停与跳转不漂移。
- 长音开关、HDR 调节持久化和扩展亮度渲染；提高 HDR 设置确实提高离屏线性亮度输出。
- 600 次相同尺寸请求只执行一次测量，改变尺寸触发新的测量。
- 长短句收缩等待、快速交替防抖、宽度上下限和前缀链尺寸稳定。
- 原生窗口动画的中间帧保持顶部和水平中心，承载歌词的视图身份与 bounds 不变。
- 自适应单行到双行切换时，主歌词第一帧与先前下一句的像素一致。

使用两份本机快速歌词经过正式解析器进行了时序模拟：分别包含 372 和 753 行，固定 100 ms 检查能覆盖 319 和 647 行，新的自适应检查覆盖全部 372 和 753 行。这验证的是时序调度，不代表在任意系统负载下都能保证每行实际绘制。测试歌词内容、缓存文件和私人路径不包含在源码或发布包中。

Release 构建、严格签名校验及安装后二进制一致性检查通过。macOS 27 原生窗口验证了自适应设置、当前歌词与翻译排版；独立动效预览验证了 HDR 滑杆，亮度设置修改后可持久化。
