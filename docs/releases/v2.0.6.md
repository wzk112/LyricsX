# LyricsX 2.0.6

发布者：Zikai Wang。发布包适用于 Apple Silicon Mac，macOS 26 及以上；构建号 212。

## 修复与改进

- 暂停和切歌时，在播放器桥接层确认空快照；短暂缺失信息不会清空歌曲、封面或歌词。可靠的暂停状态可以独立于进度更新，避免进度读不到时误归零或继续走动。
- 正在读取时收到的播放器通知会补读；播放命令会使旧请求失效。自动模式读取 Apple Music / Spotify 时采用一致的歌曲身份，减少切换数据通道引起的重复搜索。
- 自动搜索补查歌名关键词，并从 Apple 的公开音乐目录查询同一歌曲 ID 对应的其他语言名称。歌名音译、变音符号和不同文字系统均可参与匹配；目录没有收录的别名仍可能需要手动搜索。
- 处理 `feat.`、`Full Ver.`、波浪线分隔的副标题和合作歌手顺序。对同一歌曲中明确并列的不同文字歌手署名（如“雨良 Amala”）建立搜索别名；获得新别名后重新评分已有候选并补查新关键词。Live、Remix、Cover 等版本说明不会被直接抹掉。
- 各来源搜索有共同时间上限，先收集候选再选择；慢源或失败的请求不会丢弃已有结果，切歌会取消旧搜索。别名查询有内存缓存和请求频率限制。
- 时长只作辅助判断。歌名和歌手准确匹配时，即使最后一句歌词比歌曲结束早很多也可以采用；名称不完整时继续用时长辅助排除不同版本。
- 严格与宽松匹配都保留逐字、双语和来源优先级。逐字标签要求可用、递增、覆盖原文的多个时间段；空翻译、仅标点或原文的大小写/全角重复不再标成双语。原始 LRCX 内容与时间标签不改写。
- 纯音乐、正在搜索或没有可显示歌词时，悬浮窗使用较小的封面、歌名和歌手卡片。卡片和普通歌词使用同一中心锚点；大窗口临时贴边不会覆盖小卡片的位置，重新缩小时恢复原锚点。
- 搜索读取设置页面使用的同一个偏好存储，保存来源顺序、严格匹配、逐字/双语开关；新搜索使用最新设置。现有缓存仍优先复用，当前歌曲可用“按当前优先级重新搜索”更新。
- 在“设置 → 通用”加入“在 Dock 中显示”，与菜单栏显示开关独立。

## 纯音乐占位识别

只对不超过三行的非空原文做全文匹配，支持跨行拼成一句的占位文案。不会因为正常歌词中包含“纯音乐”或 `instrumental` 就隐藏整首歌；无时间轴的真实纯文本歌词也会保留。

可识别的主要字符与词组如下，大小写、全角、空格、标点和外围音符不影响匹配：

| 类别 | 词组 / 形式 |
| --- | --- |
| 中文 | 纯音乐／純音樂、无歌词／無歌詞、没有歌词／沒有歌詞、暂无歌词／暫無歌詞、未填词／未填詞、无填词／無填詞、没有填词／沒有填詞、间奏／間奏、伴奏、纯伴奏／純伴奏 |
| 中文句式 | 此歌曲为／此歌曲為、本曲为／本曲為等前缀；“没有填词的”等限定；“请欣赏／請欣賞”“请您欣赏／請您欣賞”“敬请欣赏／敬請欣賞”“请聆听／請聆聽”等结尾 |
| 英文 | instrumental、instrumental music／only／version、interlude、no lyric(s)、no lyrics available、lyrics unavailable／not available、music only、this song is instrumental、this song has no lyrics |
| 日文 | インスト、インストゥルメンタル、歌詞なし／歌詞無し、歌詞はありません／歌詞がありません、間奏 |
| 韩文 | 연주곡、가사 없음、가사가 없습니다、가사가 없어요 |
| 其他 | musique instrumentale、sans paroles、sin letra(s)、kein Text、ohne Gesang、sem letra(s)、strumentale、senza testo、без слов、инструментал、инструментальная музыка |
| 符号占位 | 仅音符、符号、标点和空白组成的短文档 |

这是明确的规则表，并非对任意歌词做语言推断；新出现的不同文案可继续补充。

## 安装

下载 `LyricsX-2.0.6.zip`，解压并将 `LyricsX.app` 拖到 `/Applications`。默认继续使用 LRCX 缓存。

SHA-256：`98bebea8eca41eff32b48e3316171601e7703a8192bedae567557c472a675782`。

发布包采用 ad-hoc 签名，没有开发者证书到期日，也没有 Apple Developer ID 公证。首次打开若被系统拦截，在 Finder 打开一次后，到“系统设置 → 隐私与安全性”选择“仍要打开”。若提示损坏，请先重新下载、解压并核对校验文件；确认来源后可参考 README 的隔离属性处理方法。

## 验证

`swift test` 执行本地回归测试。跨语言联网验证使用真实罗马音歌曲，约 7 秒从 LRCLIB、网易云和 QQ 音乐得到 6 个可用版本，包含日文原名；这是一次实测，不保证所有歌曲或网络环境都有相同结果。

原生窗口截图检查了紧凑卡片；自动回归覆盖卡片/歌词反复切换的位置，以及拖动、锁定、点击穿透和控件归属。

新增两首真实歌曲的无缓存自动选择验收，使用“酷狗 → 网易云 → QQ → LRCLIB”来源顺序、开启双语与逐字优先：

| 播放器标题 | 自动选择 | 双语 | 逐字 |
| --- | --- | --- | --- |
| DaiDaiDaiDaiDaikirai | QQMusic / ダイダイダイダイダイキライ | 是 | 是 |
| 雪降り ~ 雪が降っている ~ (feat. 結月ゆかり) [Full Ver.] | QQMusic / 雪降り ~雪が降っている~ | 是 | 是 |

验证调用正式自动选择流程，并绕过缓存；不把手动选择结果当作自动搜索成功。两首合计约 5 秒完成，此耗时仅代表当次网络情况。安装后还连续采样了 Apple Music 的暂停、跳转与切歌，未观察到空播放源闪现；Dock 显示开关的运行状态也已核对。

可选验证命令：

```sh
LYRICSX_LIVE_SOURCES=1 swift test --filter liveRomanizedSongResolvesAndSearchesNativeTitle
LYRICSX_RENDER_QA=build/qa swift test --filter renderCompactCardForVisualInspection
LYRICSX_LIVE_REPORTED_SONGS=1 swift test --filter liveReportedSongsAutomaticallyChooseBilingualWordLyricsWithoutCache
```

跨语言目录查询依据 Apple 的 [Search API](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/Searching.html) 和 [ID lookup](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/LookupExamples.html)，只补充搜索名称，播放器封面仍由当前播放源提供。
