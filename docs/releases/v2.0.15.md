# LyricsX 2.0.15

维护者：Zikai Wang

修复悬浮歌词退出、刷新和高度计算，重新整理设置，并按显示器能力限制 HDR。

## 窗口刷新

- 歌词连续绘制改为跟随各自原生窗口的显示刷新回调，注册到通用运行循环模式；主窗口进入交互或最小化过程时，悬浮窗仍可继续收到帧回调。
- 移除悬停计时器中的重复尺寸检查，位置没有变化时不再重复设置歌词宿主坐标。
- 行级时间推进同样使用通用运行循环模式，保留快速歌词边界检查以及暂停、隐藏后的低频调度。
- 主窗口可见性变化不再作为每一行的渲染参数传递，播放指示和切歌动画分别在局部读取该状态，减少隐藏瞬间的视图重算。
- 隐藏主窗口时同时冻结其进度控件和歌词选中行，重新显示时恢复当前播放进度；悬浮窗与播放器状态继续更新。
- 每个窗口独立停止帧回调；关闭、移除视图会释放刷新连接，过期的附着回调不能重新启动已经移除的视图。保留逐字、辉光、HDR 和换句效果。

原生显示同步机制使用 Apple 提供的 [displayLink API](https://developer.apple.com/documentation/appkit/nswindow/displaylink(target:selector:))。这仍是在主线程上绘制，系统或其他工作长时间阻塞主线程时不能保证零丢帧。

## 歌词退出与高度

- 旧句立即向上模糊淡出，通常在 0.16 秒内结束；高速歌词按间隔缩短。只保留最近一条退出行，旧回调不能移除新行，暂停不会把残影冻结在后面。
- 普通进入曲线更舒缓，上限从 0.58 秒调整到 0.64 秒；下一句仍从预览位置上移放大，辅助文字保留独立入场，标题和歌手不随普通换句播放动画。
- 只根据实际显示过的行建立交接；跳转、换文档、恢复窗口不会凭空生成上一句。逐字刷新缩小到主歌词，静止的翻译和下一句不随逐字时间反复重建。
- 高度变化立即开始缩放，移除 0.65 秒等待和小高度差忽略规则，保留固定宽度、顶部锚点和非线性动画。
- 测量和显示使用一致的字号、换行，避免“预留两行，实际缩成一行并贴底”形成上方空白。过长文本最多两行，必要时减小字号；增量歌词继续保持已有文字稳定。

## 设置与 HDR

设置重排为通用、播放器、悬浮窗、歌词、动效、搜索，并将开发者选项单独列出。缓存位置、导入导出、Apple Music 写入、令牌和批量恢复搜索集中到开发者选项。所有原有操作保留，各设置附用途和相关数据、联网、交互或性能影响说明。

HDR 使用 Apple 的 [潜在扩展亮度能力](https://developer.apple.com/documentation/appkit/nsscreen/maximumpotentialextendeddynamicrangecolorcomponentvalue) 判断兼容性，避免把尚未启用 HDR 内容的屏幕误判为不支持。没有支持的显示器时开关禁用并显示“不支持”；每个窗口也检测所在屏幕，在普通屏幕上绘制普通辉光。检测随显示器变化更新，无轮询；HDR 亮度和长音效果仍保留。

## 信息卡片

无歌词、纯音乐、前奏与间奏不再强制缩成 400 pt 宽度，统一沿用悬浮窗设定宽度。只将高度收至约 108–120 pt；封面大小和文字字号随宽度温和调整，长歌名最多两行，歌手一行，整体居中。转换到正常歌词时顶部、水平中心和宽度保持稳定。

## 验证

常规回归串行运行通过，包括搜索、缓存、播放同步、限时退出、暂停退出、高速换句、像素换行一致性、HDR 支持与 SDR 降级、固定宽度、位置记忆，以及 320、400、620、1000 pt 信息卡片居中和长标题边界检查。两项原生刷新测试另在独立进程中通过；本机设置页面和独立动效预览也已检查。HDR 在本机显示为支持，普通屏幕回退使用模拟环境的像素测试验证。未使用外接 SDR 实物屏幕测试。

原生刷新测试覆盖：

- 窗口交互循环内持续推进歌词时间，停止后无排队重启。
- 主窗口开始最小化或关闭后停止其帧回调，同时另一个窗口继续刷新；主窗口恢复后重新刷新，暂停后再次停止。

```sh
swift test --no-parallel
LYRICSX_WINDOW_QA=1 swift test --filter WindowFrameTests
./scripts/build.sh release
```

## 安装

下载 `LyricsX-2.0.15.zip`，解压并将 `LyricsX.app` 拖到 `/Applications` 替换旧版。现有缓存与偏好继续复用。沿用 ad-hoc 签名；首次打开提示的处理方式见 [README](https://github.com/wzk112/LyricsX#安装)。
