# LyricsX 2.0.10

维护者：Zikai Wang

修复关闭严格匹配后，LRCLIB 的准确标题仍压过来源与功能偏好的问题；完善自动搜索的逐字／双语回退和完成条件，并补齐悬浮窗辅助文字模式。

## 搜索与排序

- 仅严格匹配保留准确标题优先层级。关闭后，可信标题变体按时间轴、功能偏好、来源顺序排序；细微标题分差只用来打破平局。
- 同时开启两项偏好：逐字兼双语 > 仅逐字 > 仅双语 > 普通同步歌词。仅开启双语优先时，双语先于逐字；两项都关闭时按来源顺序。
- 自动搜索在各来源完成有效查询轮次后，应用已有最佳版本。取得逐字或双语后，补搜最多再等待约 8 秒；经过验证的新别名会重开补搜机会，总预算仍为 24 秒。
- 最高优先级来源达到全部偏好条件可立即完成；中文仅逐字、外语仅双语也能完成并保存，不再因缺少另一项长期等待。
- 已完成的缓存和手动选择继续复用。需要替换当前歌词时，使用“设置 → 歌词来源 → 按当前优先级重新搜索”。不删除缓存、不改动逐字时间轴。
- 手动搜索在更改排序配置后清除旧分数；精简模式重试合并结果后仍保持每源 12 个版本上限。完整搜索保留更多版本。

## 悬浮窗

辅助文字增加完整的五种选择：仅翻译、仅下一句、翻译或下一句、翻译和下一句、关闭。空白、缺失或与原文相同的翻译不会阻止“翻译或下一句”回退；没有下一句时不显示空白行。旧设置兼容，回退时保持预留窗口高度。

## 维护与性能

- 将版本排序与搜索调度从 `LyricsStore` 拆分为独立实现，辅助文字使用统一枚举，避免界面和窗口尺寸各自维护字符串判断。
- 搜索只检查新增或重新评分的候选，不再每次遍历全部候选判断完成条件。
- 歌词文档变化时更新逐字和纯音乐状态，播放计时器和界面复用结果。
- 补搜截止使用可取消的一次性任务；暂停、隐藏窗口与减少动态效果的既有节流策略保留。

## 验证与安装

回归覆盖严格／宽松排序、仅一种功能时的回退、慢来源第二轮升级、来源不结束时的有限等待、延迟别名唤醒、手动重试上限、五种辅助文字模式和持久化，以及播放、缓存和窗口原有回归。

本次联网验证（不读取已有歌词缓存）：《稻香》选择 QQ 音乐逐字版，约 9.7 秒；《In My Feelings》选择网易云双语版，约 10.7 秒；《雪降り》选择 QQ 音乐逐字双语版，约 5.2 秒。均正常确认最终结果。耗时和可用版本会随歌词源状态变化。

```sh
swift test
LYRICSX_LIVE_PRIORITY=1 swift test --filter liveAutomaticPriorityAndFeatureFallback
./scripts/build.sh release
```
