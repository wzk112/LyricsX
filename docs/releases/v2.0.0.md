# LyricsX 2.0.0

这是 Swift 重构版的第一个正式发布版本，目标系统为 macOS 26 及以上。

## 安装

下载 Release 中的 `LyricsX-2.0.0.zip`，解压后把 `LyricsX.app` 拖到 `/Applications`。本机已安装的版本由本次构建替换，歌词缓存目录不会改变。

如果 macOS 提示“无法打开”或“无法验证开发者”：

1. 先在 Finder 中双击一次应用，让系统记录这次尝试。
2. 打开“系统设置 → 隐私与安全性”，在安全性区域点击“仍要打开”，确认后再启动。
3. 如果提示应用已损坏，重新从 Release 下载并解压，不要从聊天软件的预览目录直接运行；仍然失败时在终端执行 `xattr -dr com.apple.quarantine /Applications/LyricsX.app`，然后再次打开。

这是因为本 Release 使用当前机器的 ad-hoc 签名，未使用 Developer ID 和 Apple 公证票据。Apple 官方说明：分发到 Mac App Store 之外的应用应使用 Developer ID 并提交 notarization；未公证应用可以在“隐私与安全性 → 仍要打开”中由用户明确放行。

## 签名有效期

本次包的签名身份是 ad-hoc（`-`），它没有 Developer ID 证书期限，也没有公证信任。它适合本机安装和源码验证，不能让其他 Mac 自动绕过 Gatekeeper。

长期公开分发需要 Apple Developer Program 的 Developer ID Application 证书、Hardened Runtime、secure timestamp 和 notarization。Developer ID 证书通常少于五年；但 Apple 说明，只要应用是在证书有效时签出并带有安全时间戳，用户已经安装的应用在证书过期后仍可运行，开发者需要更新证书来签署新版本。证书被撤销时，应用可能无法安装或启动。不要使用“永不过期”的假签名：那不是 macOS 支持的分发方式。

本机可以用以下命令确认包状态：

```sh
codesign -dv --verbose=4 /Applications/LyricsX.app
codesign --verify --deep --strict /Applications/LyricsX.app
spctl --assess --type execute /Applications/LyricsX.app
```

在没有 Developer ID 和 notarization 凭据的机器上，最后一条被 Gatekeeper 拒绝是预期结果；使用上面的“仍要打开”流程即可验证应用本身。

## 缓存格式迁移

本次已将原 LyricsX 缓存目录中的 918 个 `.lrcx` 文件转换为标准 `.lrc`，并在 `/Users/andywang/Music/LyricsX-lrcx-backup-2026-09-11` 保留了 918 个原文件作为回滚备份。新搜索结果默认保存为 `.lrc`；已有 `.lrc` 或 `.lrcx` 仍可读取，应用新版本时会更新原文件，不另建重复缓存。

标准 LRC 保留原文、时间戳、翻译和偏移；LRCX 特有的逐字 `tt` 标记不写入标准 LRC。应用内逐字动画仍可显示已有带标记的文档，导出到标准 LRC 后仅保留行级同步。

## 主要变化

- 原生 macOS 玻璃悬浮窗，背景适量模糊，文字保持对比度。
- 锁定、解锁、点击穿透、隐藏四个控制按钮；解锁会立即恢复拖动。
- 控制条与歌词拖动同步；穿透时控制条仍可点击。
- 歌词切换的模糊淡入淡出、响应式窗口、多分辨率字号。
- 歌词来源优先级与双语优先开关。
- 保留菜单栏播放、搜索、导入导出、Finder 定位、错误歌词停用、Apple Music 写入等功能。
- 播放快照、进度、封面和缓存写入经过身份校验；63 项核心回归测试和 Release 构建通过。

完整修复和验证边界见 [`REGRESSION_FIXES_2026-09-11.md`](../modernization/REGRESSION_FIXES_2026-09-11.md)。
