## 悬浮窗按钮与窗口行为

控制条固定为四个按钮，顺序和含义不随模式改变：

| 按钮 | 行为 |
| --- | --- |
| 打开主窗口 | 打开 LyricsX 播放页面 |
| 锁定 / 解锁 | 锁定禁止移动；解锁同时关闭点击穿透，恢复歌词区域拖动 |
| 点击穿透 | 只切换穿透；开启时锁定位置，关闭时保留锁定状态 |
| 隐藏 | 隐藏悬浮窗，可从主窗口、菜单栏或 ⌥⌘L 恢复 |

控制条在普通和锁定状态下直接嵌入歌词窗口；只有点击穿透时才迁入独立的子面板，保证歌词面板忽略鼠标事件时按钮仍可点击。三个模式均在鼠标进入时显示控制条，离开后淡出；穿透时也能通过原生鼠标位置检测重新唤出。鼠标经过隐藏适用于锁定状态，只淡出歌词及背景，保留鼠标下方的控制条；解锁状态优先保证拖动。

拖动使用 NSPanel 的原生 performDrag，正文和空白均为拖动区域，固定控制区域排除。**构建 203 修正了 202 的拖动方案：拖动期间控制条始终可见，与歌词共用同一个窗口和渲染表面。** 不使用定时器追赶坐标，也不在松手后重新对齐。测试在 12 次连续移动的每一步检查控制条仍可见、所属窗口一致、屏幕位置偏移一致；快速拖动时鼠标采样短暂落在窗口外也不会收起按钮。拖动结束才保存位置。解锁同时关闭穿透，将同一个控件视图迁回歌词窗口。

## 玻璃、间距和动效

- 桌面背景由 NSVisualEffectView 的 behindWindow 模式做适量模糊，上层使用完整强度的 NSGlassEffectView.clear。两层共用同一圆角轮廓，文字在独立前景绘制，保留深色文字阴影及可调背景浓度。没有另外绘制外框或整窗阴影。
- [Apple 的 behindWindow 说明](https://developer.apple.com/documentation/appkit/nsvisualeffectview/blendingmode-swift.enum/behindwindow)明确该模式使用窗口背后的桌面或窗口内容混合并模糊。单独截取透明窗口时，系统截图的灰色/透明背景不代表桌面上的最终合成效果。
- 移除悬浮窗歌名前的播放条。保留逐字高亮、滚动歌词及歌词切换动画；主窗口底部的播放指示器仍在。
- 主句与辅助文字的间距为 max(10, 主句字号 × 0.44)，翻译与下一句间距为 max(8, 辅助文字最大字号 × 0.6)，窗口高度使用同样的间距计算。
- 原文、翻译和下一句作为一组切换。旧句仅做约 0.09 秒淡出，不再停留为模糊残影；新句约 0.50 秒从 3 pt 模糊与 3 pt 位移恢复清晰。减少动态效果时停止这些位移动画。
- 主窗口切歌使用更轻的 3 pt 模糊和 0.45 秒恢复，不再大幅压低整页透明度。非当前歌词的模糊随距离连续过渡。

## 尺寸、进度与状态

- 主窗口最小布局 520 × 420 pt；宽度不足 780 pt 或内容高度不足 430 pt 时，封面、歌曲信息、控制区改成紧凑布局，歌词独占下方空间。主歌词按可用宽度缩放，翻译允许换行。
- 新默认悬浮窗宽度为 520 pt；已有自定义宽度保留。原文、翻译、下一句均可单独调整字号，辅助内容可选翻译、下一句、两者或不显示。
- 偏移减号 / 加号扩大到 32 × 32 pt，禁用主窗整块背景拖动以免误抢按钮事件。负偏移延后歌词，正偏移提前歌词，重置不更改播放器进度。
- 预览移入独立窗口，拥有自己的时钟，不再修改生产播放会话。正式播放不再注入测试歌曲、封面或歌词；缺少封面时使用中性占位图。
- 重复播放器快照复用同一解码封面，切歌立即清理旧封面，异步结果校验歌曲身份；封面解码最长边限制为 640 px。
- 播放进度视图独立更新，只有活动逐字行观察高频时间；暂停、窗口不可见时降低时钟频率。主窗口不可见时暂停其播放指示器及逐字高亮绘制。

## 设置、菜单栏和原缓存

设置窗口标题为「设置」，使用侧栏分类。新增菜单栏图标显示开关，歌词可与图标合并或独立显示，关闭后可从 Dock、主窗口设置或 ⌥⌘O 恢复。

菜单栏包含播放控制、歌词偏移、搜索 / 重搜、Finder 定位、停用错误歌曲歌词、按专辑停用 / 恢复、写入 Apple Music、导入 / 导出、资料库、设置、关于、检查更新、退出。停用是可恢复的搜索策略，不删除原歌词缓存。

保留原有缓存路径与 LRC/LRCX 读取。已有歌词直接加载；调整偏移在原文件保存。本次实际点击测试引入的偏移已恢复，未重建整个歌词缓存。

## 搜索优先级与缓存更新（204）

“设置 → 歌词来源”新增来源排序和“双语优先”（默认开启）。来源支持拖动手柄、上移/下移按钮，以及恢复默认顺序；停用来源不参与搜索，顺序和开关均持久保存。

联网来源保持同时搜索。自动选择和手动搜索列表共用同一评分规则：先校验歌曲名、歌手及时长，优先精确歌名、有时间轴的版本，然后考虑双语偏好、用户来源顺序和细微匹配质量。关闭双语优先后，来源顺序可优先于是否有翻译。空白翻译或重复原文不算双语。只允许更高分的结果替换自动选择，避免返回顺序改变最终结果。

已存在的本地缓存仍然优先读取，不因为修改排序自动下载一遍。偏好从下一次搜索生效；设置页提供“按当前优先级重新搜索”。

在搜索结果点击“使用”后会自动更新此歌曲原缓存；自动选出的最佳结果也会在搜索结束时保存，即使之后其他来源失败，已接受的结果仍保存。仅浏览结果或修改排序不覆盖缓存。保存时除检查本进程的路径记录，也查找磁盘已有文件，因此刚启动便手动应用新版本时也能替换旧 `.lrc`，不会另建重复 `.lrcx`。回归测试实际应用另一份双语歌词，使用全新缓存实例读取新版，并检查目录仍只有原文件。

## 播放器封面与内嵌歌词（205）

- Apple Music 的 JXA 接口可以返回歌曲信息，但封面属于 Apple Event 的 picture 数据，不能当作普通 URL 读取。播放器桥接现在仅在歌曲身份变化时调用原生 AppleScript，将 `raw data of artwork 1` 写入受控临时文件并立即解码；临时文件在读取后删除，避免每秒重复读取封面。
- Apple Music 内嵌歌词每次快照都安全读取，空内容不会锁死后续重试；带时间戳的歌词和纯文本歌词都可作为本地候选，纯文本不会被伪造时间轴。
- Spotify 等播放器返回的 HTTP 封面会先升级为 HTTPS；系统媒体通知中的 `data:image/...;base64,...` 封面也会正确解码。歌曲身份仍只由播放器、歌曲元数据和持久 ID 决定，封面变更不会重新触发歌词搜索。

- 在真实 Apple Music 播放中观察到歌曲和歌词持续切换；实际点击减号显示 -0.1 s、加号显示 +0.1 s。设置页已通过原生截图检查分类及滑杆布局。

仍需区分的验证边界：自动化工具无法直接向无边框面板发送拖动手势（noWindowsAvailable），因此该项使用原生窗口属性和事件分流回归验证；多台物理显示器、不同缩放率、长时间待机唤醒尚未完整实测。玻璃与动画的观感仍以桌面实际合成为准。

功能兼容边界：检查更新当前查询上游发布页，不使用原项目的 Sparkle 自动覆盖此重构版；菜单栏长歌词限制 36 字并提供完整提示，尚未复刻旧版滚动长文字。写入 Apple Music 带有歌曲身份校验，未为测试改写用户音乐资料库。以上不能视为全部旧功能已通过等价验收。
