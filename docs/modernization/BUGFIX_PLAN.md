# LyricsX 修复计划

日期：2026-09-11  
状态：待实施；本轮只审查代码、整理问题和修复方案。  
适用版本：当前本地 Swift 重构版，分支 `codex/swift-modernization`。  
依据：用户反馈、设置页面截图、当前源码和上一轮验证记录。

当前版本仍有影响日常使用的交互和同步问题，不能以“编译成功、单元测试通过”作为已经完成整个项目重构的依据。接下来先修复状态与交互，再调整视觉效果。

## 1. 本轮明确要求

- 锁定悬浮窗以后，仍然能直接点击悬浮窗上的按钮解锁。
- 修复隐藏、重新显示，以及暂停后恢复显示的行为。
- 修复歌曲进度不准、跳回、停住和拖动后不同步。
- 悬浮窗更透明，保留原生 Liquid Glass 的折射和边缘效果。
- 设置窗口标题只使用“设置”；删除“让 LyricsX 更像你”。
- 删除主页“为音乐留一点空间”等宣传性文案。
- 修复设置分类挤在一起、折叠为“…”及控件布局问题。
- 继续复用现有歌词目录和文件，不重复下载、迁移或建立第二份歌词缓存。
- 对其他问题做有证据的排查，每一项都写清复现步骤和验收结果。

## 2. 已确认的问题与待复现的问题

“代码确认”表示源码中存在该路径；不等于已经确认它是用户这次所有异常的唯一原因。“待复现”需要在实际播放器和窗口中进一步检查。

| 编号 | 优先级 | 问题 | 依据与判断 |
| --- | --- | --- | --- |
| O-01 | P0 | 锁定后无法在悬浮窗解锁 | **代码确认。** `panel.ignoresMouseEvents = overlayLocked` 让整个窗口忽略鼠标；锁按钮也只把值设为 `true`，没有解锁动作。 |
| O-02 | P0 | 隐藏后显示不符合预期 | **代码确认存在冲突；用户具体触发步骤待复现。** 显示由“启用”和“非暂停”共同决定；手动开启也可能立即被暂停隐藏条件挡住。 |
| O-03 | P0 | 播放读取故障使悬浮窗消失 | **代码确认。** 任何读取错误都会调用 `freeze()`，并设置 `isPlaying = false`；这又会触发“暂停时隐藏”。连接失败被当成了暂停。 |
| T-01 | P0 | 歌曲进度停在旧位置或周期性回退 | **代码确认存在错误计算。** 原始媒体时间戳补偿被截断到 3 秒，随后每次轮询又重设本地时间锚点。旧的有效时间锚点会被误当成新采样。 |
| T-02 | P0 | 快速拖动进度时，最后一次操作无效 | **代码确认。** `commandPending` 为真时直接丢弃新命令，但界面已经先执行乐观跳转，因此界面可能显示从未成功提交的位置。 |
| T-03 | P0 | 跳转后被旧进度覆盖 | **代码确认保护不足。** 目前仅屏蔽 0.8 秒，没有等待对应播放器确认，也没有按命令编号匹配结果。 |
| T-04 | P1 | 瞬时读取失败、字段缺失引起播放状态抖动 | **代码确认。** 缺失位置默认 0，缺失播放状态默认暂停；读取失败也立即冻结。需区分未知状态、确认暂停与真正断开。 |
| U-01 | P1 | 设置菜单挤成“…” | **截图确认外观异常。** 当前为固定 600×620 的 sheet，内部直接使用默认 `TabView`。默认导航适配与尺寸约束是排查入口，具体框架布局原因尚未独立复现。 |
| U-02 | P1 | 文案不符合要求 | **代码与截图确认。** 设置标题、主页标题旁、无歌曲占位处存在宣传性文案。 |
| V-01 | P1 | 悬浮窗不够透明 | **代码确认额外底色。** `.glassEffect(.clear)` 下叠加了 12% 黑底，并强制深色外观；实际透明度还受系统显示设置和背景影响。 |
| W-01 | P1 | 主窗口关闭后，设置／资料库打开不稳定 | **结构风险，待复现。** 打开设置依赖主窗口中的闭包及 sheet；多个 sheet 使用独立布尔值，缺少统一的窗口路由。 |
| C-01 | P1 | 已有缓存没有命中或被错误覆盖 | **代码确认边界不足。** 缓存按歌名／歌手精确找文件，曲目身份与文件名的区分字段不同；文本、同步歌词替换时也沿用原扩展名，需补充格式及版本判定。 |

P0：阻塞日常使用，优先解决。P1：本轮稳定版交付前完成。

## 3. 悬浮窗：锁定、穿透与隐藏分别管理

### 3.1 锁定的含义

“锁定位置”只限制移动，不关闭整个窗口的鼠标事件。锁定按钮是双向切换：

| 状态 | 拖动歌词区域 | 锁按钮 | 隐藏按钮 |
| --- | --- | --- | --- |
| 未锁定 | 可以移动 | 点击锁定 | 可用 |
| 已锁定 | 不移动 | 点击解锁 | 可用 |
| 已锁定且开启点击穿透 | 歌词内容区域把点击交给下层应用 | 仍可点击解锁 | 仍可用 |

设置中将“锁定位置”和“歌词区域点击穿透”拆成两个开关，菜单栏文案也同步修改。已有 `overlayLocked = true` 的配置迁移为“锁定位置”，默认不强制开启点击穿透，避免继续困住用户。

锁定时，悬浮窗右上角保留可识别的锁按钮；悬停后显示完整控制条。鼠标移到控制条时不消失、不改变按钮位置；隐藏按钮有独立点击区域，不能被窗口拖动手势抢走。

### 3.2 点击穿透的实现边界

首先修好普通锁定与解锁，再接入穿透模式。

穿透模式下，歌词内容面板可以设置 `ignoresMouseEvents`，控制条使用单独、紧贴悬浮窗的非激活小面板保持可点击。两者共用显示状态和位置计算，一起移动、隐藏、跨屏和恢复。

不能仅依赖 SwiftUI 的 `allowsHitTesting(false)` 或父窗口内视图返回空命中，假定事件一定会穿过整个窗口交给其他应用。也不能要求用户把鼠标放上去后才恢复事件，因为完全穿透的窗口可能收不到进入事件。

控制条必须只占用可见按钮区域，避免制造遮挡下层应用的透明大窗口。全屏空间中的层级与窗口关联行为需要实机检查后固定实现。

### 3.3 隐藏与恢复的规则

建立一个独立的悬浮窗显示状态管理对象，分别保存：

- 用户是否启用悬浮窗。
- 自动隐藏原因：确认暂停、没有歌曲等。
- 本次是否由用户显式要求显示。
- 实际窗口是否已显示。
- 当前播放器连接健康状态。

统一处理主窗口按钮、菜单栏、全局快捷键和悬浮窗隐藏按钮。状态变化立即更新窗口，不依赖播放动画每帧轮询设置。

| 操作／事件 | 应有行为 |
| --- | --- |
| 点击悬浮窗“隐藏” | 隐藏歌词及控制条；用户启用状态改为关闭，切歌、恢复播放和唤醒不能擅自打开。 |
| 菜单栏、主页或快捷键显式“显示” | 立即显示；即使当前暂停，也暂时覆盖自动隐藏，让本次操作可见。 |
| 已启用“暂停时隐藏”，播放器确认暂停 | 正常自动隐藏；用户显式显示产生的本次覆盖除外。 |
| 从暂停恢复播放 | 若用户仍启用悬浮窗，则恢复显示；同时结束本次显式显示覆盖，下次暂停继续按设置处理。 |
| 一次读取超时或暂时失联 | 不视为暂停，不改变用户启用状态；保留最后可信内容并标记连接异常。 |
| 关闭主窗口／设置窗口 | 不影响悬浮窗和歌词同步服务。 |
| 重启应用 | 恢复用户的启用和锁定选择；临时“显式显示覆盖”不跨重启保存。 |
| 换显示器、切空间、睡眠唤醒 | 保持隐藏意图；需要显示时恢复到可见区域，不留下孤立控制条。 |

## 4. 播放进度：先修数据语义，再修跳转确认

### 4.1 已找到的错误计算

当前媒体适配层返回的是原始播放位置和原始时间戳；它没有提前把时间推算到现在。应用却使用：

```text
位置 = 原始位置 + min(3 秒, 当前墙钟时间 − 原始时间戳)
```

例如，播放位置锚点是 10 秒，时间戳在 20 秒前，播放器一直正常播放，此时应约为 30 秒。现有计算却得到 13 秒；下一次轮询仍返回同一锚点时，又被重设为 13 秒。这可以造成歌词停住或每秒回退。

不能通过简单增大“3 秒”掩盖问题。要区分：

1. **原始时间锚点的年龄**：持续播放时，一个较旧的时间锚点仍可能有效。
2. **最近一次成功联系播放器的时间**：用于判断连接是否过期。
3. **界面动画的本地单调时钟**：用于两次采样间平滑更新。

### 4.2 新的采样契约

播放快照增加或明确以下字段：

- 播放器标识、曲目标识、播放器连接代次。
- 请求序号、采样开始和结束的单调时间。
- 原始位置、原始时间戳、时间戳是否可信。
- 已知的播放状态／速率；缺失字段保持未知，不转换成暂停或 0。
- 最近成功采样时间，以及跳转确认所关联的命令编号。

按来源区分处理：

| 来源 | 处理方式 |
| --- | --- |
| 系统播放中心，带有效原始时间戳 | 按确认的播放状态和速率推算至接收时间，再映射到单调时钟；不把锚点年龄硬截为 3 秒。 |
| 专用播放器读取，返回当下位置 | 以采样时间区间估计采样点，计入读取延迟；不重复补偿已经推算过的时间。 |
| 只有封面／歌名更新，没有进度 | 只更新元数据，不重置播放时间。 |
| 时间戳缺失、异常或与速率矛盾 | 标记低可信度，短期保留可信状态并重新读取；必要时切换专用来源。 |
| 持续失败，超过连接超时 | 停止本地外推并显示连接问题；不伪造“已暂停”。 |

先记录真实样本确认来源字段含义，再实现上述转换。墙钟只参与源时间戳转换；运行中的动画始终用单调时钟。系统时间跳变、未来时间戳和非有限值需要有明确处理。

同一歌曲正常播放时，小幅采样抖动不应让文字或进度条往返；真实向后跳转、单曲循环和重新播放必须立即允许回退。不能用“位置永远取最大值”解决回退问题。

### 4.3 跳转与连续操作

建立命令协调器，维护“待提交—已发送—等待确认—成功／失败”状态。

- 拖动时预览目标位置，松手后提交。
- 多次连续拖动合并为最后一个目标；不因为前一次命令还在执行就丢掉最后一次。
- 点击歌词与拖动进度使用同一提交路径。
- 按曲目、来源和命令编号匹配确认；旧请求不能覆盖新操作。
- 播放器返回的位置进入目标附近的允许范围后才确认成功。播放中要考虑确认期间自然前进的时间。
- 超时或失败时回到最新可信位置，并显示简短错误；不长期保留虚假的已跳转位置。
- 切歌时立即取消上一首的拖动预览和待确认命令。
- 暂停状态下跳转，确认后仍保持暂停，不能靠时间外推悄悄前进。
- 时长未知或播放器不支持 seek 时禁用进度跳转，避免当前“0 到 1 秒”的假滑块。
- 连续播放／暂停操作按最终意图处理；上一首／下一首保持有序，不能静默丢弃。
- 停止、休眠、切换播放器时取消未完成命令，旧任务结束不能重新启动轮询。

### 4.4 来源选择与恢复

自动模式应保持一个稳定的主来源。回退时不能简单选择“第一个正在运行的应用”，否则两个播放器都打开时可能读到暂停的 Apple Music，而实际播放的是另一款应用。

优先根据系统报告的播放器、活动播放状态和最近一次有效来源选择；来源切换使用独立代次隔离旧回调。短暂故障先重试，确认故障再回退，避免每次采样在两种身份格式之间跳动、重复搜索歌词。

需核查系统返回的曲目 ID 是否可能是字符串。目前 `uniqueIdentifier: Int?` 遇到非整数值可能使整个快照解码失败，应采用宽容解析或忽略不使用的字段。

## 5. 设置窗口与界面文案

### 5.1 设置改为独立窗口

使用独立的 SwiftUI Settings 场景或由统一路由管理的设置窗口，不再依赖主窗口 sheet。

窗口标题只写 **设置**。左侧固定分类，右侧只显示所选分类内容：

| 左侧分类 | 右侧内容 |
| --- | --- |
| 通用 | 登录时启动、菜单栏、快捷键 |
| 播放器 | 来源选择、连接状态、重新连接 |
| 悬浮窗 | 显示、锁定、内容点击穿透、暂停隐藏、宽度、字号、背景浓度 |
| 歌词 | 翻译、中文显示、时间偏移说明 |
| 歌词来源 | 来源启用、优先级（如实现）、Musixmatch 令牌 |
| 缓存 | 当前路径、选择目录、打开目录、读取状态 |
| 关于 | 版本、许可和项目链接 |

建议初始尺寸约 800×640 pt，最小尺寸约 680×520 pt；实际以 macOS 27 下的布局检查为准。左栏保持约 160–180 pt 的可用宽度，分类不能折叠为“…”；内容不足时滚动右栏，不缩挤导航。

字号、宽度和透明度均采用“标签／当前值 + 同组滑块”的完整设置项，不把标签和滑块拆成两个独立 Form 行。路径与解释文字允许换行，长路径可中间截断但保留复制与打开操作。

统一从菜单栏、主窗口按钮及 ⌘, 打开同一个设置窗口，重复点击只置前已有窗口。主窗口未打开时也可使用。

## 6. 更透明的悬浮窗

1. 移除默认 12% 黑色衬底，检查宿主视图和面板是否存在额外背景。
2. 保留单层原生 `glassEffect(.clear)`，避免玻璃下再叠加额外模糊层。
3. 默认背景衬色设为零；提供“背景浓度”设置，仅调节可控的衬色强度，不把整个窗口和歌词一起变淡。
4. 评估取消强制深色对玻璃效果的影响，并根据浅色、深色和复杂背景检验文字对比度。
5. 字体和控制按钮保持清晰；用适度文字阴影改善可读性，避免为了透明度牺牲歌词。
6. 检查锁定、悬停和控制条出现时材质是否保持一致，避免突然变成灰色不透明块。
7. 遵循系统“降低透明度”，开启时采用可读的实色背景。

“背景浓度”不能承诺精确控制系统 Liquid Glass 的光学透明率。系统玻璃仍会根据环境调节；验收以真实桌面背景上的观感为准，不能只看捕获单个窗口时的灰底截图。

## 7. 一并排查的其他问题

### 7.1 旧缓存与保存

继续直接使用现有目录。上次只读检查结果为 911/911 个 LRCX 可解析，其中 522 首有逐字时间轴、177 首有翻译；这只证明解析兼容，不证明播放中每首都能正确匹配。

本轮补查：

- 精确文件名命中优先；对 Unicode 标准化、大小写、全半角和空白差异增加保守的内存索引。
- 本地化歌名、多个歌手、不同专辑／现场版本不能盲目模糊匹配；有歧义时让用户选已有文件。
- 必要的曲目别名映射只保存小型索引，不复制歌词正文、不批量改名旧文件。
- 同歌名／歌手的不同版本不能无提示覆盖已有文件。
- 只调偏移时保留原文件和附件；替换纯文本与同步歌词时使用正确格式与扩展名。
- 自动重搜失败且仍显示旧歌词时，不对旧缓存做无意义写入。
- 更换缓存目录时，旧保存任务不能误写到新目录；请求与写入绑定确定的存储位置。
- 首次读取、预览和资料库扫描不修改原文件；真正编辑只原子写入对应文件。
- 偏移写回采用结构化修改，尽可能保留未知 LRCX 附件、元数据及原始内容。
- 退出时等待已发起的必要保存，避免偏移尚未落盘应用已关闭。

### 7.2 导入、搜索和窗口生命周期

- 文件选择面板打开时记录对应曲目；用户选完之前已经切歌时，不把文件无提示绑定到新歌。
- 搜索、资料库、设置各有明确路由，避免多个展示状态同时为真。
- 关闭主窗口后服务、菜单栏和快捷键仍然正常；重新打开不创建重复时钟或重复观察者。
- 快捷键注册失败应能被发现，不能界面写着可用但实际没有注册成功。
- Finder 双击 LRC／LRCX 的文件打开事件需要实际处理；仅声明文件类型不等于完成导入。
- 控件加载钥匙串等工作不阻塞设置页面首屏。
- 暂停时动效静止，窗口不可见时减少动画刷新；连接校准不依赖窗口可见性。

## 9. 验收矩阵

下列为目标标准，不代表当前已经达到。时间指标以播放器可提供的精度为前提，须区分稳定模拟源和真实播放器。

| 场景 | 操作 | 验收条件 |
| --- | --- | --- |
| 原地解锁 | 锁定→移到锁按钮→点击解锁，重复 20 次 | 均可完成；锁定时不移动，解锁后可拖动。 |
| 点击穿透 | 开启穿透，点击歌词区域和控制条 | 歌词区操作下层应用；锁／隐藏按钮仍可用，无额外透明区域拦截。 |
| 隐藏与恢复 | 从悬浮窗隐藏，再分别用菜单、主页、快捷键显示 | 每个入口都可靠；不会显示后立即被同一暂停状态挡回。 |
| 暂停隐藏 | 开启暂停隐藏，暂停→恢复→暂停；穿插手动隐藏 | 自动显示只在用户仍启用时发生，手动隐藏优先。 |
| 瞬时故障 | 正常播放时注入一次读取错误，再恢复 | 不伪报暂停、不误隐藏、不跳回 0；故障与播放状态分开。 |
| 旧时间锚点 | 连续返回同一个 20 秒前的有效锚点 | 时间持续正确推算，无每秒回拉；模拟源误差目标 ≤100 ms。 |
| 连续播放 | 对照实际播放器持续播放至少 10 分钟 | 不停住、不累计漂移；分别记录采样误差、显示误差及异常次数。 |
| 连续拖动 | 30→90→12 秒，加入 1–2 秒命令延迟 | 最后一次有效目标最终被执行；确认后不被较早请求覆盖。 |
| 拖动时切歌 | A 歌拖动中切换 B 歌，再松手 | A 的拖动值和命令不作用于 B。 |
| 暂停跳转 | 暂停→点击某行歌词 | 进度与歌词正确更新且仍暂停。 |
| 重复／回放 | 单曲循环、播放结束后重播、手动后退 | 允许真实时间回退，重新定位歌词，无旧曲目残留。 |
| 多播放器 | 同时打开两个播放器，其中一个播放 | 自动模式跟随正确来源；切换后旧请求不覆盖新来源。 |
| 睡眠与显示器 | 睡眠唤醒、断开外屏、切换全屏空间 | 无重复轮询和孤立控制条；窗口可见且保持用户隐藏意图。 |
| 设置分类 | 逐个打开分类，调整窗口和系统文字尺寸 | 无“…”挤压、无重叠；所有设置可达，必要时只滚动内容区。 |
| 独立设置 | 主窗口关闭后从菜单栏／⌘, 打开设置 | 正常打开同一设置窗口，不依赖主窗口重新建立闭包。 |
| 缓存复用 | 读取原目录歌曲及已知名称差异样本 | 命中原文件则不联网、不增加副本；歧义不自动覆盖。 |
| 文件保存 | 调偏移后立刻退出并重开 | 对应文件保留最新偏移与逐字／翻译附件；其他文件无变化。 |
| 透明度 | 浅色、深色、复杂壁纸；锁定／悬停；降低透明度 | 默认更透明，文字清晰；控制状态切换不出现突兀灰块。 |

真实播放器首轮覆盖 Apple Music；Spotify、网易云、QQ 和浏览器按本机可运行状态逐个验证，无法测试的组合明确记为“未验证”，不能只根据接口连通就宣称全兼容。

当前修复构建已有 48 项回归测试通过；旧时间戳、字段缺失、seek 确认与失败恢复已有确定性覆盖。锁定后原地解锁及点击穿透控制条已在打包后的 AppKit 窗口中实际操作通过。全屏空间、外屏热插拔、睡眠唤醒以及 Spotify、网易云、QQ 的长时间播放仍按矩阵继续验证；测试数量本身不是完成标准。
