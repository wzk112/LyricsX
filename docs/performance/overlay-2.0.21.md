# 悬浮窗帧率对比

2026-09-13，在 M5 Pro、120 Hz 内置屏幕上使用 Release 构建测试。测试窗口为 620 pt，使用默认 Liquid Glass、26% 透明度、80% 磨砂，保留逐字、长音辉光、EDR、翻译与下一句。测试采用独立模型和原创测试歌词，不读取真实播放器或写入真实歌词文件。

## 方法与结果

顺序为隐藏、120 帧、60 帧、60 帧、120 帧、隐藏。每段预热 1 秒、采样 6 秒。进程 CPU 使用 `getrusage` 的进程累计时间差计算；GPU 活跃率取自系统 IOAccelerator PerformanceStatistics，每 0.5 秒采样一次。CPU 百分比以一个逻辑核心为 100%。

| 指标 | 隐藏 | 120 帧 | 60 帧 |
| --- | ---: | ---: | ---: |
| 渲染进程 CPU，平均 | 2.65% | 13.81% | 8.40% |
| 整机 GPU 活跃率，平均 | 42.58% | 49.42% | 48.95% |
| GPU 样本范围 | 0–50% | 43–56% | 46–54% |

60 帧在这一轮减少约 39% 的进程 CPU 时间。该结果不是 GPU 占用或电池功耗的降幅。GPU 样本是整机数据，包含其他应用和 WindowServer，波动大于两种帧率之间的差异。短段 Metal 跟踪也显示 GPU 工作主要归入 WindowServer 和其他进程，无法直接将所有合成耗时算给悬浮窗。当前没有可靠的逐应用 GPU 瓦数数据。

因此默认保留跟随屏幕，并提供 60 帧选项。此版本同时去掉重复的前景合成分组；辉光直接绘制字形，去掉重复的字形遮罩与填充，SDR 和 EDR 亮度回归通过。尚未证明这些整理对应确定的整机 GPU 百分比收益。不能承诺把刷新率减半就将 GPU 占用减半。

## 重复测试

设置 `LYRICSX_GPU_QA` 为一个临时输出目录，然后单独执行：

```sh
swift test -c release --no-parallel --filter OverlayGPUPerformanceTests
```

测试会输出带时间戳的阶段文件和进程 CPU 数据，方便与外部 GPU 采样工具对齐。不要与其他原生窗口测试同时运行。正式比较应保持背景、屏幕亮度、供电和其他应用负载一致，并重复交错采样；设置页与实际播放器不要同时参与测试窗口。
